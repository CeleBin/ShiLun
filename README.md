# ShiLun

把纠结交给转盘，把快乐留给餐桌。

ShiLun 提供自定义转盘、附近餐饮查询和下饭视频推荐。登录后可跨设备同步转盘和私有收藏，也可以投稿、反馈和设置推荐偏好。

## 使用和运行

需要 Node.js 22.12 或更新版本，建议 Node 24。

```powershell
cd C:\Users\14375\dinner-helper
npm install
npm run dev
```

开发地址以启动输出为准，默认 http://127.0.0.1:5173/。本地开发和生产预览都接入同一 `/api/app` 服务端处理器，不需要额外启动 Vercel CLI。

```powershell
npm test
npm run build
npm run preview -- --port 4173 --strictPort
```

## 本次实现

- 访客：原有自定义转盘、浏览器保存、8 条历史及通用推荐继续使用。
- 账户：使用必填且唯一的用户名和密码注册、登录。用户名查重和登录不区分大小写。密码使用 scrypt 哈希保存。
- 收藏：可收藏推荐卡片，也可粘贴 B 站完整链接。粘贴 BV 视频链接时会去掉追踪参数，并读取公开标题、UP 主、时长和封面。读取失败时仍可收藏链接；收藏按视频去重，仅本人可见。
- 转盘：增删候选、抽选和清空历史后自动同步到账户；失败时保留本页更改并提示恢复操作。
- 迁移：通过预览确认后才导入访客记录，支持合并/替换/取消；超 16 项需自行选择，菜单与历史不静默覆盖。
- 投稿：登录用户投稿，待审/通过/拒绝与审核回复在“我的账户”查看；管理员核对元信息后收录。
- 反馈：登录后提交意见或从视频卡片报告问题，查看处理状态及回复；管理员可按用户、类型和状态查看处理。
- 偏好：时长可多选；喜欢、收藏和不感兴趣会影响内容推荐。
- 内容管理：管理员录入、编辑、上下架视频；版本检查阻止旧页面覆盖其他管理员的新修改。

不会把 B 站外链点击写成播放或完播，不上传/托管视频，不获取原站观看历史。

## 附近餐饮

在「我的候选菜单」点击「从附近选」，允许浏览器定位后，可展开附近 2 公里内的餐饮类型查看该类型下的店铺。类型和店铺独立勾选，可以一起加入转盘。已在菜单上的选项会跳过，转盘最多保留 16 项。超过 16 字的店名会在弹窗预览缩短后的转盘名称。

搜索会拉取高德允许返回的所有分页，每次搜索最多 200 条，去重后按类型展示。搜索结果和未提交的勾选保存在当前浏览器。再次打开直接显示上次结果，点「刷新附近店铺」才使用新的定位发起查询，查询失败时仍可用上次结果。

把高德开放平台的「Web 服务」Key 填入本地 `.env.local` 的 `AMAP_WEB_SERVICE_KEY`，然后重启开发服务。Vercel 项目配置同名变量后重新部署。线上定位需要 HTTPS。

定位坐标仅用于当次高德查询，ShiLun 不保存坐标。菜单只保存用户加入的餐饮类型和店名。

## 配置账号存储

1. 在 Upstash 建立供 ShiLun 使用的 Redis 数据库，取得 REST URL 和 REST Token。账号、登录会话和应用数据都保存在该数据库。
2. 复制 `.env.example` 为 `.env.local`，填写这两个值；在 Vercel 项目中也配置同名环境变量。
3. 可选：新管理员注册并登录后，在同一站点打开 `/api/auth?action=me`，把返回的 `userId` 填入 `SHILUN_ADMIN_USER_IDS`。多个 ID 用逗号分隔。
4. 重新启动本地开发；Vercel 修改环境变量后需重新部署。账号接口通过服务端函数读取 Upstash。

| 环境变量 | 用途 | 可进入前端 |
|---|---|---|
| `UPSTASH_REDIS_REST_URL` | Redis REST 地址 | 否 |
| `UPSTASH_REDIS_REST_TOKEN` | Redis REST 凭证 | 否 |
| `SHILUN_ADMIN_USER_IDS` | 可选的管理员用户 ID 白名单 | 否 |

来源示例（不要包含结尾 `/`）：

```text
https://shilun.cbnb.online,http://127.0.0.1:5173,http://localhost:5173
```

本地运行 `npm run dev` 后可在 `http://127.0.0.1:5173` 注册测试。生产 Cookie 自动使用 Secure 标记。请妥善保管密码，目前没有找回入口。不要把 `.env.local` 提交到 GitHub。

切换为用户名登录后，旧邮箱会话会失效，测试用户可重新注册。新账号使用独立存储空间，旧账号的存储记录和视频库仍保留。

Redis 两项配置均为空时，只提供内置精选；一旦配置了数据库，读取失败会显示暂不可用并暂停视频展示，避免把已下架的旧种子重新推荐。账号及账户写操作在数据库不可用时明确失败。

## 账户数据边界

- 访客键为 `shilun.wheel.v1`，仅属于这个设备、浏览器和网站来源，不生成文件或跨设备同步。
- 登录账户的转盘、收藏、偏好和私有记录保存在 Upstash，所有私有操作在服务端校验本人归属。
- 登录不会自动上传访客菜单；导入需要预览确认。退出后恢复独立访客状态，不把上一账户的内容复制给访客或下个账号。
- 菜单和历史最多 16 项 / 每项 16 个可见字符 / 最近 8 条。多设备版本冲突时重新读取和比较，不静默覆盖；抽选保存重试不会再次随机抽选。
- 账户内可清除 ShiLun 的个人数据；该操作不会删除登录身份。公共已发布内容与管理审计不按个人收藏级联删除。
- 收藏默认私有，已知下架内容保留私人链接并提示状态，不自动重新公开；输入链接本期仍仅支持 B 站完整视频/节目地址。

## 数据与运维边界

所有 Redis 键使用 `shilun:v2:` 命名空间；个人文档按 user ID 哈希分开，公共库、投稿、反馈和审核审计在独立文档。服务端使用 Redis Lua compare-and-set，禁止以简单读写覆盖处理并发。

当前是适合早期运营的有界文档存储：

- 每文档最多 1.5 MB，公共库最多 500 视频，投稿 1000 条、反馈 2000 条（每用户各 100 条）。
- 每账户最多 200 收藏，最近 500 条推荐事件（活跃写入时裁剪到 30 天窗口），最近 100 个推荐请求上下文（1 天有效）。
- 操作去重、管理审计和抽选去重指纹有 5000 项上限；达到上限明确报错，不自动删掉审核或幂等依据。
- 用户操作限流 60 次/分钟；公开请求按服务端连接来源限流。Vercel 代理后的连接来源可能合并，因此公开限流并非精确终端用户配额。

生产前应通过 Upstash 控制台/官方备份方式确认备份与恢复；在记录接近上限前做备份和维护归档。当前没有自动归档任务、后台保留期清理或运营容量告警；非活跃账户旧事件不会靠浏览器被自动删除，需通过运维清理或用户清除。后续增长可将日志/投稿迁移到分页与独立记录结构，不应长期放大单文档上限。

账户清除是两个文档的可重试更新，不是跨文档事务；部分失败明确报告，重试继续完成，不声称已全部清除。安全备份和归档应保护私人数据。

## 内容和推荐

`src/data/videos.ts` 保留已核实种子和来源；数据库未创建公共文档时由这些条目初始化业务读视图，管理员第一次写入持久化。配置服务后，通过后台维护公共内容，不能仅修改种子就假设会覆盖已存在库。

推荐策略版本 `behavior-tag-matches-v7`。用 B 站公开标签和可确认的美食分类，从当前有效的喜欢和收藏累积兴趣。手动偏好只保留时长，命中任一所选时长加 2 分，与行为兴趣合并排序。只选一档且其余条目全命中时，最后一条优先选其他已知时长。每批最多 6 条，尽量分散作者，有行为匹配时优先安排 4 条排序结果和 2 条探索。

扩库时会尝试读取新视频的公开标签。已有 BV 视频可用 `node scripts/expand-bilibili.mjs --tags-only` 预览补标，加 `--apply` 写入缺少的标签。读取暂时失败的视频继续按主动偏好和精选推荐。

`node scripts/expand-bilibili.mjs --search-food --target=106` 按关键词从 B 站找「探店试吃」和「烹饪制作」，按 BV 号去重。用标题和原站标签确认分类，默认预览候选。核对后可加 `--apply` 写入，`--target` 是写入后的已发布视频总量目标。

“喜欢/不感兴趣/撤销”保留独立事件；卡片发起的事件关联推荐请求和策略，曝光以卡片可见为准，事件和写入均去重。不做设备指纹，访客不建立跨会话画像。

内置种子和已发布片库分别维护。维护者核实主题、风格和时长后可为视频标注。
